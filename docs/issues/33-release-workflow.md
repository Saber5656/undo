# Title

Release workflow: universal binary, checksums, provenance

## Summary

Add the tag-triggered release pipeline: build a universal2 macOS binary (arm64 + x86_64, lipo), package tarballs, generate SHA256SUMS and GitHub build-provenance attestations, and publish a draft GitHub Release; document the release process in RELEASING.md.

## Context

Distribution decision: GitHub Releases + Homebrew tap (product decision 2026-07-07). Release integrity per DESIGN §12.8: checksums + provenance now; Apple code signing/notarization is a known unknown (U7) and explicitly out of v1 (brew installs are not quarantined).

## Scope

- `.github/workflows/release.yml`, trigger `push: tags: ['v*.*.*']`:
  1. gate job: full CI green required (reuse workflows via `workflow_call` or re-run lint+test+e2e here — choose re-run for isolation);
  2. build on `macos-15`: `rustup target add x86_64-apple-darwin`; `cargo build --release` for `aarch64-apple-darwin` + `x86_64-apple-darwin`; `lipo -create -output undo` both; verify `lipo -archs` shows both, `codesign -dv` NOT expected (unsigned OK);
  3. smoke: run `./undo --version`, `./undo doctor --json` (sandbox HOME) on the runner;
  4. package `undo-v<ver>-macos-universal.tar.gz` (binary + LICENSE files + README);
  5. `shasum -a 256` → `SHA256SUMS`;
  6. `actions/attest-build-provenance` on the tarball (workflow `permissions: id-token: write, attestations: write, contents: write` — minimal set, job-scoped);
  7. create **draft** GitHub Release with tarball + SHA256SUMS + autogenerated notes; publishing the draft is a manual maintainer step (merge ≠ release principle).
- Version consistency guard: tag `vX.Y.Z` must equal `CARGO_PKG_VERSION` (job fails otherwise).
- `RELEASING.md`: step-by-step (bump version PR → tag on main → workflow → verify checksums/attestation `gh attestation verify` → publish draft → then issue 34's tap bump); rollback note (delete draft, never delete published releases — yank via new patch).

## Detailed Requirements

1. Third-party/GitHub actions SHA-pinned; workflow permissions minimal per job (top-level `contents: read`, elevated only in the release job).
2. Cross-compiled x86_64 slice must be smoke-tested at least via `file`/`lipo` inspection (no Intel runner needed for v1; note `macos-26-intel` as an optional matrix upgrade).
3. Tarball layout documented in RELEASING.md (tap formula in 34 depends on it — binary at archive root).
4. Dry-run path: `workflow_dispatch` input `dry_run: true` runs everything but skips release creation (used for CI validation of this issue).

## Acceptance Criteria

- [ ] `workflow_dispatch` dry run green end-to-end on a scratch tag/branch (artifacts inspectable, universal binary verified).
- [ ] Version-mismatch guard demonstrated (scratch run with mismatched tag fails fast).
- [ ] `gh attestation verify <tarball> --repo <owner>/undo` succeeds on the dry-run artifact.
- [ ] RELEASING.md complete; draft-only behavior confirmed.

## Validation

Dry-run workflow link + verification transcript in PR.

## Dependencies

02, 31 (e2e as release gate).

## Non-goals

Apple codesigning/notarization (U7 — v2 decision), crates.io publish (not in distribution scope), auto-changelog tooling.
